# ② 사전 확인

출력 범위: 관련 자료가 있는지까지만. 판정하지 않는다.

돌리기 전에 두 가지를 준비한다.

| 준비물 | 이유 |
|---|---|
| 웹 검색이 되는 세션 | 규제기관·기사를 찾아야 한다 |
| 유출사고 DB 파일 | 내부 자료다. 첨부하지 않으면 AI가 찾지 못한다 |

대상 조직은 이름만 적지 말고 공식 도메인을 함께 적는다. 이름만 주면 동명의 다른 조직을 조사한다.

```
②[역할]
유출 주장 하나에 대해 공식 자료가 존재하는지 조사한다.
판정하지 말고 자료의 존재와 내용만 정리한다.

[입력]
대상 조직:
공식 도메인:
주장 규모:
주장 시점:
게시 시각:

[대상 문자열 일치]
도메인은 문자 단위로 대조한다. 하이픈 위치나 TLD가 다르면 다른 조직이다.
검색에 유사 상호나 유사 도메인이 나와도 대상으로 바꾸지 않는다.
  예) example-mall.co.kr 은 example-m-all.com 이 아니다
대상을 특정하지 못했으면 특정하지 못했다고 적는다. 비슷한 것으로 채우지 않는다.

[찾을 것]
1. 규제기관 자료
   - 개인정보보호위원회, KISA, 금융위, 해외 규제기관
   - 있으면: 발표일, 확정 내용, 규모, 제재 여부

2. 피해 조직 공식 입장
   - 공식 공지, 보도자료, 고객 안내
   - 있으면: 발표일, 인정인지 반박인지, 원문 인용

3. 언론 보도
   - 조직 확인이 인용된 후속 보도만
   - 있으면: 매체, 날짜, 인용된 조직 발언

4. 국내 사고 명단(유출사고 DB) 검색
   - 대상 조직 / 보도된 행위자 / 보도된 유출 위치 세 가지로 검색
   - 있으면: 해당 줄의 사건명, 시기, 규모

5. 팀 DB 대조 (먼저 한다)
   **사건 ID로 찾지 않는다.** 노션이 자동 부여하므로 조사 시점에는 없다.
   사람이 읽는 값으로 찾는다. 대상 조직, 대상 도메인, 게시자 핸들, 원문 URL.

   ```
   python tools/notion_find.py 수집 <대상 도메인>
   python tools/notion_find.py 수집 <게시자 핸들>
   python tools/notion_find.py 검증 <대상 조직>
   ```

   찾은 결과에 따라 갈린다.

   | 결과 | 무엇을 하나 |
   |---|---|
   | 수집 DB에 같은 게시글이 있다 | **새로 채번하지 않는다.** 그 줄에 이어 붙인다 |
   | 상태가 검증 완료다 | **검증 DB에서 기존 판정을 먼저 읽는다.** 재검증이 필요한지부터 판단한다 |
   | 같은 게시자의 다른 줄이 있다 | 대조 재료다. 같은 날 여러 대상에 올렸는지 본다 |
   | 같은 대상의 다른 줄이 있다 | 재유포인지 별건인지 가른다 |
   | 하나도 없다 | 새 건이다. 그대로 진행한다 |

   기존 줄의 값을 재료로 가져온다. 게시 플랫폼, 원문 URL, 대상 조직 같은 것이
   이미 적혀 있으면 못 봄으로 적지 않는다.

   DB를 직접 조회해 없는 것을 확인했으면 없음으로 적는다. 검색으로 못 찾은 것과 다르다.

6. 발행처 내부 검색 (조건부)
   아래 두 조건 중 하나가 맞을 때만 돈다. 목록 전체를 매번 훑지 않는다.

   조건 가. 검색 결과나 제공된 재료에서 발행처가 하나라도 확인됨
      그 사이트의 내부 검색을 이어서 돌린다.
      같은 발행처가 관련 글을 더 올렸을 수 있다.

   조건 나. 위 1~4의 범용 검색이 0건
      노션 관리 목록을 돌린다. 마지막 경로다.

   질의 형식
      https://<발행처 도메인>/?s=<대상 도메인 또는 조직명>

   - 이 검색 결과 페이지는 noindex 라 검색엔진에는 원리적으로 안 잡힌다.
     직접 호출해야만 보이고, 그래서 검색 인덱스 커버리지와 독립적으로 작동한다
   - 발행처별로 3분류해 기록한다: 해당 있음 / 해당 없음 / 조회 실패
   - 조회 실패를 해당 없음으로 적지 않는다
   - 발행처 목록은 이 프롬프트에 두지 않는다. references/publishers.md 를 본다.
     목록은 낡고, 대부분의 조회가 헛돌고, 목록에 올라간 쪽으로 수집이 편향된다

[검색 질의 규칙]
각각 별개 질의로 돌린다. 한 질의에 섞지 않는다.

  1. 대상 도메인 문자열 단독. 따옴표로 묶는다
  2. 대상 도메인 + 영문 1단어 (breach 또는 leak 또는 database)
  3. 판매자 핸들 단독
  4. 주장 규모 + 국가

식별자를 한 줄에 다 넣지 마라. 자료 종류마다 담고 있는 식별자가 다르다.

  자료 종류        핸들            규모            도메인   필드 구성
  언론 기사        안 적는 경우 많음  적음            적음     요약해서 적음
  벤더 알림        안 적음          안 적는 경우 있음  적음     상세히 적음
  집계 계정 게시물  적는 경우 있음    적음            적음     안 적음

넷을 합치면 어느 자료도 만족시키지 못하는 질의가 된다.
검색엔진은 질의어를 많이 포함한 문서에 높은 점수를 준다.

[문서 채택 시 리터럴 확인]
채택하려는 문서는 열어서 대상 문자열이 실제로 들어 있는지 확인한다.
없으면 그 문서를 버린다.
검색 결과 목록만 보고 채택하지 마라.

[중단 조건]
공식 출처 1건과 독립 출처 1건을 확보하면 멈춘다.
0건이면 사용한 수단명을 적고 멈춘다.
질의를 무한히 변형하지 마라.

[검색 부재 기재 규칙]
자료를 찾지 못했을 때 없다로 적지 않는다. 아래 형식으로 적는다.

  못 봄 — 수단: <검색 도구 또는 URL>, 질의: <문자열 그대로>, 일시: <YYYY-MM-DD>

검색으로 못 찾은 것은 부재의 근거가 아니다.
부재로 단정할 수 있는 것은 공식 게시판이나 규제기관 자료처럼
대상 범위가 확정된 곳을 직접 열람했을 때뿐이다.

단일 수단 0건을 독립 검증 없음의 근거로 검증 분류에 반영하지 않는다.

[출력]
■ 규제기관
발견: 확인함 / 없음 / 못 봄(이유)
자료:
발표일:
내용 원문 인용:

■ 조직 공식 입장
발견: 확인함 / 없음 / 못 봄(이유)
성격: 인정 / 반박 / 조사 중 / 기타
자료:
발표일:
내용 원문 인용:

■ 언론
발견: 확인함 / 없음 / 못 봄(이유)
매체·날짜:
인용된 조직 발언:

■ 유출사고 DB
검색어(3종):
일치 항목:
일치 정도: 조직명만 / 조직명+규모 / 조직명+시기 / 없음

■ 팀 DB 대조
수집 DB 질의와 결과:
  같은 게시글 줄: 있음(제목과 링크) / 없음
  같은 게시자 다른 줄:
  같은 대상 다른 줄:
검증 DB 질의와 결과:
  기존 판정: 있음(사건명, 검증 분류, 진위, 검증일) / 없음
기존 줄에서 가져온 값:
재검증이 필요한 이유: (기존 판정이 있을 때만)

■ 발행처 내부 검색
돌린 조건: 가 (발행처 확인됨) / 나 (범용 검색 0건) / 해당 없어 안 돌림
발행처별로 한 줄씩. 해당 있음이면 URL을 붙인다.
  <도메인>        해당 있음 / 해당 없음 / 조회 실패

■ 검색 수단 기록
쓴 도구:
질의 1 (도메인 단독):
질의 2 (도메인 + 1단어):
질의 3 (판매자 핸들):
질의 4 (규모 + 국가):
일시:
중단 사유: 공식 1건과 독립 1건 확보 / 0건

■ 리터럴 확인
채택한 문서마다 대상 문자열 포함 여부
버린 문서와 사유

■ 결과에 따른 처리
아래 표에서 해당하는 줄을 지목한다. 판정을 확정하지 말고 「해당」만 표시한다.

  확인 내용                        검증분류   진위     이후
  규제기관이 사실관계 확정            A        확인됨   중단
  피해 조직이 침해 공식 인정          B        확인됨   중단
  피해 조직이 구체적 근거와 함께 반박   D 유지    허위     중단
  조직이 조사 중이라고만 발표          C        미확인   진행
  공식 입장 없음                     D        미확인   진행

■ 구체적 근거 해당 여부
조직 반박을 허위 근거로 쓰려면 아래 중 하나가 있어야 한다.
  - 내부 식별체계 불일치 (회원번호·고객번호가 자사 규칙과 다름)
  - 데이터 구조 불일치 (자사가 보유하지 않는 필드 포함)
  - 규모 불일치 (자사 보유 규모 초과)
  - 출처 불일치 (자사 시스템에서 생성될 수 없는 데이터)

"조사 결과 유출 정황 없음" 같은 일반적 부인은 해당하지 않는다.
해당 없음이면 미확인으로 두고 진행한다.

■ 사람이 판단할 것
(아래는 답하지 않고 항목만 나열한다)
- 조직 반박이 구체적 근거를 포함하는가
- 명단 일치 건이 본 건과 같은 사건인가

[금지]
- "허위다" "확인됨이다" 같은 판정을 내리지 마라
- 조직 발언을 요약하지 말고 원문을 인용하라
- 2차 보도만으로 조직 입장을 단정하지 마라. 원문 소재를 함께 적어라
- 자료를 못 찾았을 때 없다고 적지 마라. 못 봄에 수단과 질의를 적어라
- 검색이 대상을 못 찾았을 때 유사 상호로 갈아타지 마라
- 식별자를 한 질의에 섞지 마라
- 대상 문자열이 없는 문서를 채택하지 마라
- 중단 조건에 닿았으면 질의를 더 만들지 마라
- 팀 DB를 안 보고 사건 채번이 필요하다고 적지 마라
- 기존 줄에 있는 값을 못 봄으로 적지 마라
- 사건 ID로 찾지 마라. 노션이 자동 부여한다
```
