# ② 사전 확인

출력 범위: 관련 자료가 있는지까지만. 판정하지 않는다.

돌리기 전에 두 가지를 준비한다.

| 준비물 | 이유 |
|---|---|
| 웹 검색이 되는 세션 | 규제기관·기사를 찾아야 한다 |
| 유출사고 DB 파일 | 내부 자료다. 첨부하지 않으면 AI가 찾지 못한다 |

대상 조직은 이름만 적지 말고 공식 도메인을 함께 적는다. 이름만 주면 동명의 다른 조직을 조사한다.

```
②[역할]
유출 주장 하나에 대해 공식 자료가 존재하는지 조사한다.
판정하지 말고 자료의 존재와 내용만 정리한다.

[입력]
대상 조직:
공식 도메인:
주장 규모:
주장 시점:
게시 시각:

[이 단계의 순서]
아래 순서대로 한다. 뒤 단계를 먼저 하지 않는다.

  1. 팀 DB 대조   이미 아는 건인지부터 본다
  2. 대상 확인    무엇을 조사하는지 확정한다
  3. 자료 찾기    규칙을 읽고 두 갈래를 다 돈다
                   갈래 A 범용 검색
                   갈래 B 직접 조회
  4. 출력

1을 건너뛰면 같은 건을 두 번 검증한다.
2를 건너뛰면 엉뚱한 조직을 조사한다.
3에서 한 갈래만 돌면 다른 갈래에만 있는 자료를 놓친다.


[1. 팀 DB 대조]
제일 먼저 한다. 검색보다 앞이다.

**팀 DB가 없는 환경이면 건너뛴다.** 출력에 안 봄(팀 DB 없음)이라고 적고
2로 간다. 조사를 멈추거나 되묻지 않는다.
아래는 팀 DB가 있을 때다.

**사건 ID로 찾지 않는다.** 노션이 자동 부여하므로 조사 시점에는 없다.
사람이 읽는 값으로 찾는다. 대상 조직, 대상 도메인, 게시자 핸들, 원문 URL.

**새 건의 원문 URL·대상 조직·게시 시각을 함께 준다.** 그러면 줄마다 분류가 붙는다.

    python tools/notion_find.py 수집 <게시자 핸들> --url "<원문 URL>" --org "<대상 조직>" --date <YYYY-MM-DD> --handle "<게시자 핸들>"
    python tools/notion_find.py 수집 <대상 도메인> --url "<원문 URL>" --org "<대상 조직>" --date <YYYY-MM-DD> --handle "<게시자 핸들>"
    python tools/notion_find.py 검증 <대상 조직>

넷을 안 주면 목록만 나오고 분류가 안 붙는다. 그러면 사람이 눈으로 갈라야 한다.
원문 URL 은 잘라서 넣지 마라. 통째로 같아야 완전 동일 건으로 잡힌다.
게시자 핸들을 빼면 재유포와 재게시가 안 갈린다.

  분류                 무엇으로 갈랐나                무엇을 하나
  완전 동일 건          원문 URL 이 같다               새 조사를 시작하지 않는다. 그 줄에 이어 붙인다
  다른 게시자 재유포 후보  대상 같고 게시자가 다르다        신규성 판정에서 재유포를 먼저 본다. 날짜와 무관하다
  조건만 다른 같은 건    대상·게시자 같고 3일 이내        같은 배포다. 규모·가격 차이만 기록한다
  재게시 후보           대상·게시자 같고 3일 초과        재유포인지 별건인지 사람이 가른다
  같은 대상 의심        이름은 다른데 주소에 상대 이름     표기가 갈린 것일 수 있다. 사람이 확인한다
  다른 건              대상이 다르다                  대조 재료로만 본다
  확인 못 함           대상을 못 읽었다                --org 를 주고 다시 돌린다

**게시자가 다르면 날짜를 보지 않는다.** 같은 대상을 다른 사람이 올린 것 자체가
재유포 신호다. 같은 날이어도 그렇다. 원 판매자와 되파는 쪽이 같이 올리는 일이 있다.

여기에 더해 아래도 본다.

  상태가 검증 완료다           검증 DB에서 기존 판정을 먼저 읽는다.
                            재검증이 필요한지부터 판단한다
  같은 게시자의 다른 줄이 있다   대조 재료다. 같은 날 여러 대상에 올렸는지 본다
  하나도 없다                새 건이다. 그대로 진행한다

**분류는 참고다.** 3일 경계는 정한 값이고 이름 대조는 표기에 기댄다.
확정은 사람이 한다. 다만 완전 동일 건이 하나라도 있으면 멈추고 사람에게 알린다.

기존 줄의 값을 재료로 가져온다. 게시 플랫폼, 원문 URL, 대상 조직 같은 것이
이미 적혀 있으면 못 봄으로 적지 않는다.

DB를 직접 조회해 없는 것을 확인했으면 없음으로 적는다. 검색으로 못 찾은 것과 다르다.
DB는 있는데 조회가 안 되면 못 봄(이유)으로 적는다. 토큰 없음, 도구 없음처럼 이유를 적는다.


[2. 대상 확인]

2-1. 대상 문자열 일치
도메인은 문자 단위로 대조한다. 하이픈 위치나 TLD가 다르면 다른 조직이다.
검색에 유사 상호나 유사 도메인이 나와도 대상으로 바꾸지 않는다.
  예) example-mall.co.kr 은 example-m-all.com 이 아니다
대상을 특정하지 못했으면 특정하지 못했다고 적는다. 비슷한 것으로 채우지 않는다.

2-2. 대상 조직 사이트 조회
**공개 페이지는 조회한다.** 팀 결정 2026-08-19.
도메인이 실재하는지, 어떤 서비스인지, 운영 주체가 누구인지를 확인하는 데 필요하다.

  볼 수 있는 것
    첫 화면, 회사 소개, 이용약관, 사업자 정보, 고객센터
    응답 헤더, 리디렉션 경로, robots.txt, sitemap
    모바일 도메인, 계열 도메인

  기록할 것
    조회한 URL과 시각
    응답 코드와 최종 도착 경로
    운영 주체를 특정했는지, 못 했으면 왜 못 했는지

아래는 조회가 아니라 능동 행위다. **하지 않는다.**

    로그인 시도. 계정 생성. 비밀번호 추측
    관리자 경로나 백업 파일 추측 접근. 디렉터리 나열 시도
    취약점 점검 도구 사용. 대량 요청
    로그인 뒤에만 보이는 페이지 접근

전면 로그인 게이트라 공개 정보가 없으면 그대로 적는다.
운영 주체를 못 찾았으면 못 찾았다고 적고 대상 일치는 확인불가로 둔다.


[3. 자료 찾기]
두 갈래를 다 돈다. 한쪽에서 자료가 나와도 다른 쪽을 건너뛰지 않는다.

  갈래 A. 범용 검색   검색엔진 색인을 본다
  갈래 B. 직접 조회   사이트 자체 검색 DB를 본다

**우열이 아니라 보는 데가 다르다.** 서로 못 보는 것이 있다.

  갈래 A가 못 보는 것            갈래 B가 못 보는 것
  noindex 페이지. 원리적으로 안 잡힘   목록에 없는 사이트
  색인에서 빠진 문서
  순위가 낮아 묻힌 문서

발행처 검색 결과 페이지는 대부분 noindex 다. 갈래 A로는 원리적으로 안 나온다.
갈래 A가 0건일 때만 B를 도는 방식은 틀렸다. A가 약한 자료 하나를 물면
B를 안 돌게 되고, B에만 있는 강한 자료를 놓친다.

아래 3-1에서 3-5까지 읽고 나서 3-6과 3-7을 돈다.

3-1. 질의 규칙
각각 별개 질의로 돌린다. 한 질의에 섞지 않는다.

  1.   대상 도메인 문자열 단독. 따옴표로 묶는다
  2.   대상 도메인 + 영문 1단어 (breach 또는 leak 또는 database)
  3-1. 판매자 핸들 단독
  3-2. 판매자 핸들 + 성격어 (threat actor 또는 forum 또는 breach)
  4.   주장 규모 + 국가

**다섯을 모두 돌린다. 중간에 자료를 찾아도 남은 질의를 건너뛰지 않는다.**
질의마다 무엇이 나왔는지 적는다. 0건이면 0건이라고 적는다.
안 돌린 질의를 돌린 것처럼 적지 마라.

3-1과 3-2가 특히 중요하다. 같은 판매자가 여러 국가나 여러 조직에 뿌린 정황은
대상 도메인으로는 나오지 않는다. 그런 자료는 제목에 핸들이 들어가기 때문이다.

식별자를 한 줄에 다 넣지 마라. 자료 종류마다 담고 있는 식별자가 다르다.

  자료 종류        핸들            규모            도메인   필드 구성
  언론 기사        안 적는 경우 많음  적음            적음     요약해서 적음
  벤더 알림        안 적음          안 적는 경우 있음  적음     상세히 적음
  집계 계정 게시물  적는 경우 있음    적음            적음     안 적음

넷을 합치면 어느 자료도 만족시키지 못하는 질의가 된다.
검색엔진은 질의어를 많이 포함한 문서에 높은 점수를 준다.

3-2. 조회 도구
갈래 B는 도구를 가린다. 평문 요청은 대부분 막힌다.
아래 순서로 시도하고 무엇을 썼는지 출력에 적는다.

  1. 스크래핑 도구      Firecrawl 등. 프록시를 거쳐 요청한다
  2. 브라우저 도구      실제 브라우저로 연다
  3. 리더 프록시        r.jina.ai 등
  4. 평문 HTTP 요청     curl, 내장 fetch

**하나도 없으면 조회 실패로 적는다. 해당 없음이 아니다.**
도구가 없어서 못 본 것과 그 사이트에 자료가 없는 것은 다르다.

3-3. 조회 성공 판정
**200이 떴다고 조회 성공이 아니다.** 아래 셋을 다 만족해야 성공이다.

  페이지 제목이나 본문에 질의 문자열이 들어 있다
  검색 결과 페이지 형태다. 사이트 첫 화면이 아니다
  봇 차단 화면이 아니다

아래는 전부 겉보기에 성공인 실패 형태다.

  형태                              무엇인가
  200 인데 제목이 사이트 이름       그 사이트는 이 검색 경로를 안 쓴다
  200 인데 "Just a moment"          Cloudflare 챌린지
  200 인데 "Checking your browser"  Cloudflare 챌린지
  200 인데 "보안 확인 수행 중"       Cloudflare 챌린지
  200 인데 CAPTCHA 안내             봇 차단

셋 중 하나라도 아니면 **조회 실패**다. 해당 없음으로 적지 마라.

검색 페이지가 떴어도 나열된 항목이 결과가 아닐 수 있다.
**결과 0건일 때 메뉴나 인기글을 대신 보여주는 곳이 많다.**

  결과로 세려면 항목 제목이나 발췌에 질의 문자열이 들어 있어야 한다
  "No Content Found", "nothing matched" 같은 문구가 있으면 0건이다
  나열된 것이 Home, About Us, Privacy Policy 같은 메뉴 이름이면 결과가 아니다
  나열된 것이 질의와 무관한 최신글·인기글이면 결과가 아니다

결과 0건은 **해당 없음**이다. 조회 실패가 아니다. 둘을 구분해 적는다.

  조회 실패   질의가 안 돌았다. 부재의 근거가 못 된다
  해당 없음   질의가 돌았고 그 사이트에 자료가 없다. 부재의 근거가 된다

3-4. 문서 채택 규칙
채택하려는 문서는 열어서 대상 문자열이 실제로 들어 있는지 확인한다.
없으면 그 문서를 버린다.
검색 결과 목록만 보고 채택하지 마라.

3-5. 부재 기재 규칙
자료를 찾지 못했을 때 없다로 적지 않는다. 아래 형식으로 적는다.

  못 봄 - 수단: <검색 도구 또는 URL>, 질의: <문자열 그대로>, 일시: <YYYY-MM-DD>

검색으로 못 찾은 것은 부재의 근거가 아니다.
부재로 단정할 수 있는 것은 공식 게시판이나 규제기관 자료처럼
대상 범위가 확정된 곳을 직접 열람했을 때뿐이다.

단일 수단 0건을 독립 검증 없음의 근거로 검증 분류에 반영하지 않는다.

3-6. 갈래 A. 범용 검색
질의 다섯으로 아래 넷을 본다.

1. 규제기관 자료
   - 개인정보보호위원회, KISA, 금융위, 해외 규제기관
   - 있으면: 발표일, 확정 내용, 규모, 제재 여부

2. 피해 조직 공식 입장
   - 공식 공지, 보도자료, 고객 안내
   - 있으면: 발표일, 인정인지 반박인지, 원문 인용

3. 언론 보도
   - 조직 확인이 인용된 후속 보도만
   - 있으면: 매체, 날짜, 인용된 조직 발언

4. 국내 사고 명단(유출사고 DB) 검색
   - 대상 조직 / 보도된 행위자 / 보도된 유출 위치 세 가지로 검색
   - 있으면: 해당 줄의 사건명, 시기, 규모

3-7. 갈래 B. 직접 조회
발행처 사이트 검색을 직접 호출한다. 갈래 A 결과와 무관하게 돈다.

질의 형식
     https://<발행처 도메인>/?s=<대상 도메인 또는 조직명>

대상은 아래 둘이다. **목록 전체를 훑지 않는다.**

  가. 동작이 확인된 발행처
     references/publishers.md 에서 "동작" 표기가 있는 곳만.
     미확인·조회 실패 표기인 곳은 안 돈다. 대부분 헛돈다
  나. 갈래 A에서 이름이 나온 발행처
     그 사이트를 이어서 돌린다. 관련 글을 더 올렸을 수 있다

질의는 대상 도메인과 판매자 핸들 둘 다로 돈다.
핸들로만 나오는 자료가 있다. 제목에 핸들이 들어가기 때문이다.

발행처별로 3분류해 기록한다: 해당 있음 / 해당 없음 / 조회 실패
3-3의 성공 판정을 통과한 것만 해당 있음 또는 해당 없음으로 적는다.

새 발행처를 찾으면 publishers.md 표에 줄을 더한다.

3-8. 중단 조건
**두 갈래를 다 돈 뒤에 판단한다.** 중간에 발동하지 않는다.
```
