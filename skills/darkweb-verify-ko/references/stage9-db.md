# ⑨ DB 입력

사람이 ⑧에서 매긴 판정을 DB 형식으로 변환한다. 판정을 만들지 않는다.

| 절 | 어디에 | 언제 |
|---|---|---|
| ⑨-1 | 수집 DB | ⑥ 이 끝나면 바로. ⑧ 을 기다리지 않는다 |
| ⑨-2 | 검증 DB | ⑧ 판정이 확정된 뒤 |
| ⑨-3 | 행위자 DB · 포럼 DB | ③ 에서 없다고 나왔을 때만 |

## ⑨-1. 수집 DB (25칸. 자동 칸 포함)

수집 DB에는 판정 칸이 없으므로 위험도도 넣지 않는다.

**⑧ 판정을 기다리지 않는다.** ⑥ 이 끝나면 바로 넣을 수 있다.
⑥ 출력의 9번 절이 이 형식으로 나온다. 그것을 그대로 쓴다.
판정이 확정되기 전에 넣어야 다음 건에서 중복 대조가 된다.
판정을 기다리다 안 넣으면 조사한 건이 팀 DB 에 안 남는다.

```
⑨-1[역할]
게시글 확인 결과를 수집 DB 컬럼 형식으로 변환한다.
판정은 넣지 않는다. 이 DB에 판정 칸은 없다.

[입력]
⑤ 재료 합치기 출력

[규칙]
- 주장 규모는 게시글에 적힌 그대로 옮긴다.
  숫자, 단위, 쉼표, 대소문자, 띄어쓰기를 바꾸지 않는다.
  단위를 환산하거나 숫자만 남기지 않는다
- 값이 없으면 빈칸으로 두고 임의로 채우지 않는다
- 판정·신뢰도·검증 결과를 넣지 마라
- `중복 관계`와 `같은 사건`은 ③ 사전 확인에서 나온 분류를 **사람이 확정한 값**이다.
  도구가 낸 후보를 그대로 옮기지 마라. 판정자가 정한 것만 넣는다
- 중복이 아니면 `중복 관계`를 해당 없음으로 두고 `같은 사건`은 비운다
- `최근 1주`는 노션 수식이 자동 계산한다. 출력하지 마라

[자료 제목 규칙]

    <게시자 핸들> - <대상> (<포럼 또는 게시 사이트명>)

- 대상 자리에 **도메인을 적지 마라.** 대상 이름을 적는다
  맞음   AshleyWood2022 - treethink (Darkforums)
  틀림   AshleyWood2022 - treethink.kr (Darkforums)
- 도메인은 `대상 조직` 칸에 이름과 함께 적는다. 제목에는 안 적는다
- 괄호 안은 포럼 이름이다. 자체 유출 사이트면 그 사이트 이름을 적는다
- 포럼을 못 읽었으면 아래 [사람에게 물을 것] 을 먼저 한다

[사람에게 물을 것] — 출력 전에 한 번에 묻는다

**캡처와 원문 URL 은 사람만 갖고 있다.** 캡처 화면에 안 보이는 것을
AI 가 추측해서 채우면 안 된다. 아래 둘이 비어 있으면 출력하기 전에 묻는다.

    원문 URL     게시글 주소. onion 이어도 그대로 적는다
    캡처         파일명. 여러 장이면 전부

- **원문 URL 이 포럼을 정한다.** 캡처에 도메인이 없어도 URL 에는 있다.
  darkfox...onion 이면 Darkforums 다. 미러마다 앞 해시가 다르니 이름으로 적는다
- 사람이 없다고 답하면 그때 비워 두고 `비고` 에 못 본 이유를 적는다
- 묻지 않고 비워 두지 마라. 두 칸이 빠지면 ③ 중복 대조가 자유 텍스트에 기댄다

[본문 세 항목 규칙]

캡처
- 캡처에 원문 URL·포럼명·확인 시각이 안 보이면 그 사실을 한 줄 적는다

연락처
- 다른 곳에서 같은 사람인지 대조할 수 있는 식별자만 적는다
- 넣는 것  텔레그램 / TOX / Session / Jabber(XMPP) / 이메일 /
           BTC·XMR 지갑 / 쇼핑몰·개인 사이트 URL / ICQ / Discord
- 빼는 것  포럼 등급, Reputation, Points, 가입일, 게시물 수,
           아바타, 답글 수, 조회 수, 포럼 내 PM
           그 포럼 안에서만 유효한 값은 대조에 못 쓴다
- 하나도 없으면 "없음"

참고사항
- 관찰한 것만 적는다. 판정하지 마라
- 원문 전문을 옮겨 적지 마라. 캡처에 있다
- 샘플 값을 옮겨 적지 마라. 원문 URL이 대신한다

[비고와 참고사항 구분]
비고(칸)      표에서 한눈에 봐야 하는 것. 한 줄. 주로 접근 제약
참고사항(본문) 나머지 관찰 메모. 여러 줄 가능

[출력] — 컬럼명: 값 형식으로만
아래 순서 그대로 낸다. 노션 DB 칸 순서와 같으므로 위에서부터 옮겨 적으면 된다.
순서를 바꾸지 마라.

자료 제목:      <게시자 핸들> - <대상> (<포럼 또는 게시 사이트명>)
가격:           숫자만
같은 사건:      LEAK-n          (이어지는 줄. 없으면 빈칸. 여럿이면 쉼표)
게시 시각:      원문 표기 그대로
게시 플랫폼:    venue 이름
게시자 핸들:
국가:
대상 조직:
비고:           접근 제약 등 한 줄
사건 ID:        LEAK-n          (자동 부여. 미정이면 "자동")
산업 분야:
상태:           수집 / 검증 중 / 보류 / 완료
샘플:           스크린샷 / 본문 공개 / 파일 / 링크 / 없음
수집일:         YYYY-MM-DD
수집자:
원문 URL:
유출 항목:      쉼표 구분 (이름, 이메일, 전화, 계정, 주민번호, 카드금융, 기타)
주장 규모:      원문 표기 그대로 (숫자 변환 금지)
중복 관계:      아예 동일 케이스 / 재게시 / 일부 조건이 다른 같은 케이스 / 확인 못 함 / 해당 없음
통화:           USD / KRW / 기타

--- 아래는 페이지 본문에 붙인다. 칸이 아니다 ---

캡처:           파일명만 적는다
연락처:         캡처에서 읽은 식별자만
참고사항:       관찰한 것만
```

## ⑨-2. 검증 DB (24칸. 자동 칸 포함)

**위험도 다섯 칸은 노션에 있다.** 바로 쓸 수 있다.

**`수집 줄` 은 수집 DB 로 가는 관계 칸이다.** 2026-08-22 에 넣었다.
전에는 사건 ID 문자열이 두 DB 를 잇는 유일한 고리였다.
뒤에 공백이 하나 붙은 줄이 넷 있었고 대조가 거기서 깨졌다.
화면에서는 안 보인다. 그래서 문자열 대신 관계로 잇는다.

이 칸을 채우면 대상 조직, 게시자 핸들, 게시 플랫폼을 수집 줄에서 따라간다.
검증 DB 에는 그 세 칸이 없어서, 없으면 자유 텍스트로 찾는 수밖에 없다.

**2026-08-22 이전 줄은 비어 있다.** 소급해서 채우지 않기로 했다.

```
⑨-2[역할]
사람이 확정한 판정을 검증 DB 컬럼 형식으로 변환한다.
판정을 만들거나 바꾸지 않는다.

[먼저 확인할 것]
돌리기 전에 노션 DB 상태를 본다. 노션을 안 쓰면 이 절을 건너뛴다.

노션 검증 DB의 `사건 ID` 속성 종류를 확인한다.
고유 ID(№) 속성이면 자동 생성이라 입력이 들어가지 않는다.
그 경우 출력에서 빼고 수집 DB와의 연결은 관계형 속성으로 잡는다.
지금은 제목 속성이라 사람이 친다. **앞뒤 공백을 넣지 마라.**

`수집 줄` 관계 칸이 있는지 확인한다. 없으면 출력에서 뺀다.
있으면 반드시 채운다. 수집 DB 에 그 건이 없으면 ⑨-1 을 먼저 넣는다.

위험도 다섯 칸이 노션에 만들어져 있는지 확인한다.
없으면 출력에서 빼고, 만들 때까지 검증 요약 끝에 위험도 절로만 적는다.

[입력]
⑥ 출력 :

핵심 4항목 상태:
  대상 일치:
  샘플 검증:
  내용 일치:
  규모 검증:

사람이 확정한 판정:
  검증 분류:
  진위 판정:
  신규성 판정:
  판정 신뢰도:
  위험도 자산 민감도:
  위험도 즉시 악용 가능성:
  위험도 신선도:
  위험도 피해 범위:
  위험도 확산 정도:

쓴 자료:

[위험도 규칙]
- 다섯 칸을 각각 적는다. 총점 칸은 없다
- 근거는 검증 요약 끝에 위험도 절로 붙인다. 항목당 한 줄
- 진위가 미확인이어도 위험도를 깎지 않는다. 사실이면 얼마나 위험한지를 적는다
- 판단 근거가 없으면 확인불가로 적는다. 비우지 않는다

[핵심 검증 결과 규칙]
- 충족된 항목만 적는다. 노션 선택지와 글자가 같아야 한다
  대상 일치 / 샘플 확인 / 내용 일치 / 규모 일치 / 없음
- 부분충족·불충족은 이 칸에 넣지 않는다
- 충족이 하나도 없으면 빈칸

[검증 요약 규칙]
부분충족·불충족이 있으면 첫 줄에 반드시 적는다. 형식은 아래와 같다.

    부분충족: <해당 항목 이름을 쉼표로>
    불충족: <해당 항목 이름을 쉼표로>

그다음 줄부터 근거를 2~3문장으로 적는다.
해당 없는 줄은 적지 않는다. "불충족: 없음"처럼 쓰지 마라.
안 적혀 있으면 없는 것으로 읽는다.

마지막에 위험도 절을 붙인다. 다섯 항목을 순서대로 한 줄씩 적는다.

    위험도
    <항목 이름> <매긴 값> - <그렇게 본 근거 한 줄>

항목 순서는 자산 민감도, 즉시 악용 가능성, 신선도, 피해 범위, 확산 정도다.
근거는 재료에서 확인한 것만 적는다. 없으면 확인불가로 적고 왜 못 봤는지 쓴다.

[검증 자료 규칙]
한 줄에 하나씩 적는다. 종류를 앞에 쓰고 URL과 확인일을 붙인다.

    조직 공식 입장    회사 공지·보도자료·고객 안내
    규제기관 자료     개인정보위 처분, 해외 감독기관 공지
    보도              언론 기사
    벤더 리포트       ASEC, S2W, StealthMole 등
    발행처 직접 조회   발행처별 3분류 결과
    조회 도구         HIBP 등. 결과가 없어도 "해당 없음"으로 적는다
    파일 트리         출처와 총 경로 수
    사용 도구·모델    툴킷명과 모델명

- 조회했는데 결과가 없는 것도 적는다. 안 찾아본 것과 다르다
- 검색으로 못 찾은 것은 못 봄에 수단과 질의를 붙여 적는다
- 기사가 조직명을 익명 표기(A사, 국내 대형 유통사 등)했으면
  본문에 그렇게 적고, 동일 건임이 확인됐는지를 함께 적는다
  확인 안 됐으면 한계 칸에도 넣는다
- 요약 사이트는 원 출처를 적는다. 재게시 페이지를 독립 출처로 세지 마라

[대조 검사] — 출력하기 전에 돈다. 아래 여섯 가지만 본다. 이 밖의 것은 검사하지 마라

  1. 샘플이 "없음"이거나 빈칸인데  샘플 검증이 충족 또는 부분충족
  2. 주장 규모가 빈칸인데          규모 검증이 충족 또는 부분충족
  3. 유출 항목에 없는 항목을 근거로 내용 일치를 충족
  4. 원문 URL이 빈칸인데          재료 출처가 "1차 게시글 직접 확인"
  5. 위험도 다섯 칸 중 빈칸이 있음
  6. 재료 출처에 "트리"가 없는데   자산 민감도가 확인불가가 아님
  7. 수집 줄이 빈칸                 (수집 DB 에 그 건이 없으면 ⑨-1 을 먼저 넣는다)

걸린 것이 없으면 아무 말 없이 바로 출력한다.
"확인했습니다" 같은 말을 붙이지 마라.

걸린 것이 있으면 출력하지 않고 아래 형식으로 그 줄만 낸다.
질문하지 마라. 어긋난 사실만 적는다. 판정을 고치지도 마라.

    대조 불일치
    <이 출력의 칸 이름>: <값>  /  <대조한 곳>: <거기 값>

한 번에 다 낸다. 두 번 되묻지 마라.

[지적하지 마라] — 아래는 전부 정상이다

- 빈칸. 값이 없으면 비우는 것이 규칙이다 (위험도 다섯 칸은 예외)
- 미확인 · 확인불가 · 신뢰도 낮음. 기본값이다. 조직 확인율은 1.4%다
- 근거 요약이 짧은 것
- 판정끼리 어긋나는 것. 분류가 D인데 진위가 신뢰성 높음일 수 있다
- 진위가 미확인인데 위험도가 치명인 것. 사실이면 치명이라는 뜻이다
- 한계 칸에 이미 적힌 것
- 표기 · 맞춤법 · 날짜 형식 · 띄어쓰기
- 자료를 더 찾아보라는 제안
- 판정이 맞는지에 대한 의견
- 위 여섯 가지에 없는 다른 조합

[출력] — 컬럼명: 값 형식으로만

아래 순서 그대로 낸다. 노션 DB 칸 순서와 같으므로 위에서부터 옮겨 적으면 된다.
순서를 바꾸지 마라.

사건 ID:        LEAK-n YYYY-MM-DD
수집 줄:        LEAK-n           (수집 DB 의 같은 건. 사건 ID 와 같은 번호)
검증 분류:      A / B / C / D
검증 요약:      위 규칙 참조
검증 자료:      위 규칙 참조
검증일:         YYYY-MM-DD
검증자:
신규성 판정:    신규 유출 / 재유포 / 혼합 / 확인불가
재료 출처:      1차 게시글 직접 / 2차 기사·리스트업 / 트리 확보 / 대체값 사용
진위 판정:      확인됨 / 신뢰성 높음 / 미확인 / 신뢰성 낮음 / 허위
판정 변경 조건:
판정 신뢰도:    높음 / 중간 / 낮음
한계:
```

## 노션에 실제로 올리기

노션을 안 쓰면 이 절은 건너뛴다. 위 ⑨ 출력이 그대로 기록물이다.

⑨ 출력을 파일로 저장한 뒤 아래를 돈다. **미리보기가 기본이고 `--commit` 을 붙여야 쓴다.**

```
python tools/notion_row.py 검증 out9.txt
```

미리보기에 칸별로 무엇이 들어가는지, 못 넣은 칸이 무엇인지, 선택지가 어긋난 것이 있는지 나온다.

사람이 보고 결정한다.

| 상황 | 명령 |
|---|---|
| 그대로 올린다 | `--commit` 을 붙여 다시 돌린다 |
| 인용하지 않을 칸이 있다 | `--exclude "검증 자료,한계"` |
| 값을 고칠 칸이 있다 | `--set "검증자=이름"` |

셋을 함께 쓸 수 있다.

```
python tools/notion_row.py 검증 out9.txt --exclude "한계" --set "검증자=이름" --commit
```

### 규칙

    미리보기 없이 쓰지 않는다. --commit 을 사람 확인 전에 붙이지 않는다
    기존 행을 고치지 않는다. 새 행만 만든다
    선택지에 없는 값은 넣지 않는다. 오타 선택지가 생기면 DB가 지저분해진다
    못 넣은 칸이 있으면 사람에게 알린다. 조용히 넘기지 않는다

DB 이름으로 찾으므로 워크스페이스 ID를 코드에 박지 않는다.
`검증`, `수집` 처럼 이름 일부만 주면 된다.
