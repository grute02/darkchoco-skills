# 발행처 관리 목록

2단계 갈래 B 직접 조회에서 쓴다.
**갈래 A 결과와 무관하게 돈다.** 범용 검색이 0건일 때만 도는 것이 아니다.

## 왜 목록을 프롬프트에 안 두나

    목록은 낡는다. 새 발행처가 계속 생기고 되던 곳이 안 되기도 한다
    목록에 올라간 발행처 쪽으로 자료 수집이 편향된다

편향은 목록을 짧게 유지하는 것으로 줄이지 못한다.
갈래 A를 항상 같이 돌아 목록 밖 자료를 잡는 것으로 상쇄한다.

## 질의 형식

    https://<발행처 도메인>/?s=<대상 도메인 또는 조직명>

`/?s=` 는 워드프레스 검색 경로다. 발행처마다 다르므로 형식을 따로 적는다.

**워드프레스는 `/?s=<질의>` 가 `/search/<질의>/` 로 넘어간다. 정상이다.**
도착 주소가 바뀌었다고 실패로 보지 마라. 첫 화면으로 갔을 때가 실패다.

워드프레스가 아닌 곳은 이 경로가 없다. Ghost, Hugo 같은 정적·헤드리스
엔진은 서버 검색 경로 자체가 없어 첫 화면이나 404를 준다.

이 검색 결과 페이지는 noindex 라 검색엔진에 원리적으로 안 잡힌다.
직접 호출해야만 보이고, 그래서 검색 인덱스 커버리지와 독립적으로 작동한다.

## 기록 규칙

발행처별로 3분류해 적는다.

    해당 있음 / 해당 없음 / 조회 실패

**조회 실패를 해당 없음으로 적지 않는다.**
질의가 안 돌아간 것과 그 사이트에 자료가 없는 것은 다르다.
판정 기준은 stage2 의 3-3에 있다.

## 목록

돌 곳은 아래 다섯이다. 동작이 확인된 곳만 둔다.

| 도메인 | 경로 |
|---|---|
| mybroadband.co.za | `/?s=` |
| socradar.io | `/?s=` |
| dailydarkweb.net | `/?s=` |
| undercodenews.com | `/?s=` |
| dexpose.io | `/?s=` |

**돌아봤는데 안 되는 곳은 이 표에 두지 않는다.** 표에 있으면 도는 곳이다.
안 되는 이유는 사이트 사정이라 바뀐다. 기록해두면 낡는다.
다시 궁금하면 그때 한 번 돌려보는 것이 정확하다.

## 새 발행처 찾기와 추가

목록은 낡는다. 새 발행처는 **② 질의 3-1 판매자 핸들 단독 검색**에서 나온다.
그런 자료는 제목에 핸들이 들어가서 대상 도메인으로는 안 잡힌다.
지금 목록에 있는 곳도 그렇게 찾았다.

새로 나오면 위 표에 줄을 더한다. 이때 두 가지를 지킨다.

    검색 URL 형식은 실제로 한 번 돌려보고 적는다
    워드프레스가 아니면 `/?s=` 가 안 먹는다. Ghost 기반이 그렇다
