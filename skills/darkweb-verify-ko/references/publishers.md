# 발행처 관리 목록

2단계 사전 확인의 발행처 내부 검색에서 쓴다.
**이 목록은 의무 조회 대상이 아니다.** 아래 두 조건 중 하나가 맞을 때만 본다.

    조건 가. 검색 결과나 재료에서 발행처가 하나라도 확인됨
    조건 나. 범용 검색이 0건. 마지막 경로

## 왜 목록을 프롬프트에 안 두나

    목록은 낡는다. 새 발행처가 계속 생긴다
    목록에 있는 발행처가 모든 사건을 다루지 않는다. 대부분의 조회가 헛돈다
    목록에 올라간 발행처 쪽으로 자료 수집이 편향된다

## 질의 형식

    https://<발행처 도메인>/?s=<대상 도메인 또는 조직명>

`/?s=` 는 워드프레스 검색 경로다. 발행처마다 다르므로 형식을 따로 적는다.

이 검색 결과 페이지는 noindex 라 검색엔진에 원리적으로 안 잡힌다.
직접 호출해야만 보이고, 그래서 검색 인덱스 커버리지와 독립적으로 작동한다.

## 도구별 실측

2026-08-20. mybroadband.co.za 검색 경로로 잰 것이다.

| 도구 | 결과 | 성격 |
|---|---|---|
| 스크래핑 도구 (Firecrawl) | 200. 결과 반환 | 통과 |
| 브라우저 도구 | Cloudflare 챌린지 | 막힘 |
| 리더 프록시 (r.jina.ai) | **200 인데 "Just a moment"** | 막힘. 겉보기 성공 |
| WebFetch 내장 | 403 | 막힘 |
| curl | 403 | 막힘 |

**막힌 것 넷 중 둘이 200을 준다.** 상태 코드로 성공을 판정하면 안 된다.
stage2 의 3-3 조회 성공 판정을 쓴다.

## 기록 규칙

발행처별로 3분류해 적는다.

    해당 있음 / 해당 없음 / 조회 실패

**조회 실패를 해당 없음으로 적지 않는다.** 실측 3곳 중 2곳에서만 유효한 답이 나왔다.

## 새 발행처 찾기와 추가

목록은 낡는다. 새 발행처는 **② 질의 3-1 판매자 핸들 단독 검색**에서 나온다.
그런 자료는 제목에 핸들이 들어가서 대상 도메인으로는 안 잡힌다.
실제로 grayscaleinsight.com 과 mybroadband.co.za 가 그렇게 발견됐다.

새로 나오면 위 표에 줄을 더한다. 이때 두 가지를 지킨다.

    검색 URL 형식은 실제로 한 번 돌려보고 적는다
    워드프레스가 아니면 `/?s=` 가 안 먹는다. Ghost 기반이 그렇다
