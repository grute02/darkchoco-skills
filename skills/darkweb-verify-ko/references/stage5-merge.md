# ⑤ 재료 합치기

형식 변환과 출처 태그까지. 항목 배치는 사람이 확인한다.

```
⑤[역할]
흩어진 재료를 검증용 단일 양식으로 합친다.
정보를 해석하거나 보태지 말고 배치와 출처 표기만 한다.

[입력]
■ 게시글 확인 결과 (체크리스트 A~E)
■ 마스킹 결과 (④ 출력)
■ 파일 트리 분석 결과 (있으면)
■ 사전 확인 결과 (③ 출력)
■ 기사·리스트업 발췌

[합치는 규칙]
1. 같은 항목에 여러 값이 있으면 모두 적고 출처를 각각 붙인다
2. 값이 충돌하면 병기하고 충돌을 표시한다
3. 없는 항목은 상태값 넷 중 하나로 적는다. 비우지 않는다
4. 대체값을 쓴 항목은 대체 사실과 근거를 함께 적는다

[출처 태그]
[1차]  게시글 직접 확인
[2차]  기사·리스트업·벤더 리포트
[트리] 확보한 유출물의 파일 구조
[내부] 팀 DB, 일일보고, 기존 기록
[대체] 원 데이터가 없어 다른 값으로 갈음

[출처로 적기 전 문자열 확인]
출처로 적는 문서는 **대상 문자열을 실제로 포함해야 한다.**
포함하지 않으면 본 건 자료가 아니다. 아래 둘 중 하나로 처리한다.

  버린다                       주제만 비슷한 무관 자료
  행위자 대조 자료로만 표시한다   같은 판매자의 다른 대상 건

행위자 대조 자료는 본 건의 검증 분류 근거로 세지 않는다.
그렇게 표시했다는 사실을 함께 적는다.

이 확인은 검색 단계뿐 아니라 **최종 출처 목록에도 적용한다.**
문서 끝에 참고 자료를 붙일 때도 대상 문자열이 없는 것을 넣지 않는다.

**두 등급을 합치지 마라. 둘 다 적는다.**
`tree_scan` 은 파일명만 봐서 덤프 하나에 든 표 수십 개를 못 가른다.
treethink 에서 파일 단위 치명 0인데 표 단위로는 `master_tb` 가 치명 1이었다.
결함이 아니라 축의 한계다. ⑧ 위험도의 자산 민감도는 **둘 중 높은 쪽**으로 매긴다.

표 단위 등급은 **칸 이름 기준**이다. 값이 비어 있어도 등급이 안 내려간다.
`member.jumin` 은 칸이 있고 값이 0건이었다.
`sample_stats <덤프> --table <표>` 로 채움률을 보고 사람이 확정한다.
```
