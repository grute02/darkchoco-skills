# 유출 주장 검증

다크초코 팀 검증 절차다. 유출 주장 하나를 9단계로 처리한다.

## 절대 원칙 넷

이 넷은 어떤 단계에서도 어기지 않는다.

| | 원칙 |
|---|---|
| 1 | **판정은 사람이 한다.** ⑧을 대신 내리지 않는다. ⑥에서 참고 판정까지만 낸다 |
| 2 | **원본 개인정보를 AI에 넣지 않는다.** ④에서 패턴으로 바꾼 뒤 쓴다. ④의 입력만 원문이다 |
| 3 | **재료에 없는 정보를 채우지 않는다.** 모르면 못 봄으로 적는다 |
| 4 | **적신호 하나로 허위를 확정하지 않는다** |

## 상태값

빈칸으로 남기지 않는다. 넷 중 하나를 쓴다.

| 표기 | 뜻 |
|---|---|
| 확인함 | 봤고 값이 있다 |
| 없음 | 봤는데 없다 |
| 못 봄(이유) | 보려 했는데 막혔다. 이유에 수단과 질의를 적는다 |
| 안 봄 | 이번 범위가 아니었다 |

**없음과 못 봄은 다르다.** 못 본 것을 없음으로 적으면 나중에 실제로 빈 것으로 읽힌다.

## 이 스킬이 서는 자리

전체 흐름에서 스킬은 **④에서 ⑥까지를 끊김 없이 이어서 돈다.**

```
[사람이 먼저 함]
  ① 발견
  ③ 게시글 확인          체크리스트로 재료 수집. 파일 트리 확보
        |
        |  이 결과를 입력으로 넣고 스킬을 부른다
        v
[스킬이 함]  중간에 멈추지 않는다
  ② 사전 확인            팀 DB 대조를 먼저 한다. 이미 있는 건인지 본다
  ④ 마스킹              샘플 원문을 패턴으로
  ⑤ 재료 합치기          한 덩어리로
  ⑥ 판정 근거 산출        계산, 항목 점검, 참고 판정
        |
        v
[사람이 함]
  ⑦ 검토                환각·단정·누락 제거
  ⑧ 판정                다섯 축 확정
        |
        v
[필요하면 다시 부름]
  ⑨ DB 입력             질의 몇 개 받아 DB 양식대로 출력
```

**③은 스킬을 부르기 전에 사람이 준비하는 입력이다.** 스킬이 수행하지 않는다.
**⑦⑧은 스킬이 끝난 뒤다.** ⑥ 출력을 사람이 검토하고 판정한다.
**⑨는 별도 호출이다.** 조사가 중간에 끊긴 것이 아니라, DB에 넣을 때 다시 부르는 부가 기능이다.

| 단계 | 담당 | 읽을 것 |
|---|---|---|
| ① 발견 | 사람 | 없음 |
| ② 사전 확인 | **스킬** | `references/stage2-precheck.md` |
| ③ 게시글 확인 | 사람. 스킬 호출 전 입력 | `references/stage3-post.md` |
| ④ 마스킹 | **스킬** | `references/stage4-masking.md` |
| ⑤ 재료 합치기 | **스킬** | `references/stage5-merge.md` |
| ⑥ 판정 근거 산출 | **스킬** | `references/stage6-toolkit.md` |
| ⑦ 검토 | 사람. 스킬 종료 후 | `references/stage7-review.md` |
| ⑧ 판정 | 사람. 스킬 종료 후 | `references/stage8-verdict.md` |
| ⑨ DB 입력 | **스킬**. 별도 호출 | `references/stage9-db.md` |

## 어떻게 쓰나

### 기본 호출

사용자가 ③ 결과를 넣고 검증을 요청하면 ④⑤⑥을 이어서 돌리고 ⑥ 출력을 낸다.
중간에 되묻지 않는다. 재료가 모자란 항목은 못 봄으로 적고 넘어간다.

받아야 하는 입력이다. 없으면 무엇이 없는지 한 번만 알리고, 있는 것으로 진행한다.

    게시글 확인 결과 (③ 체크리스트 A~E)
    샘플 원문 또는 샘플 없음
    파일 트리 (있으면)
    ② 사전 확인 결과 (했으면. 안 했으면 스킬이 먼저 돈다)

### 단계 지목 호출

사용자가 단계를 지목하면 그 단계만 돌린다.

    "2단계만 돌려줘"        stage2-precheck.md
    "이 샘플 마스킹해줘"     stage4-masking.md
    "트리 분석해줘"         tree-analysis.md
    "검증 DB에 넣게 정리해줘"  stage9-db.md

### ⑨ DB 입력

⑧에서 사람이 판정을 확정한 뒤 부른다. 아래를 질의해 받고 DB 양식으로 낸다.

    ⑥ 출력
    핵심 4항목 상태
    사람이 확정한 다섯 축 판정
    쓴 자료

판정을 만들거나 바꾸지 않는다. 받은 것을 형식만 바꾼다.

노션에 실제로 올릴 때는 `tools/notion_row.py` 를 쓴다.
**미리보기를 먼저 내고 사람이 뺄 칸과 고칠 칸을 말한 뒤 올린다.**
사람 확인 없이 `--commit` 을 붙이지 않는다.

## 판정 다섯 축

기준 전문은 `references/stage6-toolkit.md` 에 있다. 요약만 적는다.

| 축 | 무엇을 재나 | 값 |
|---|---|---|
| 검증 분류 | 밖에서 누가 확인해 줬나 | A / B / C / D |
| 진위 판정 | 실제 데이터인가 | 확인됨 / 신뢰성 높음 / 미확인 / 신뢰성 낮음 / 허위 |
| 신규성 판정 | 새로 유출된 것인가 | 신규 유출 / 재유포 / 혼합 / 확인불가 |
| 판정 신뢰도 | 이 판정을 얼마나 확신하나 | 높음 / 중간 / 낮음 |
| 위험도 | 사실이면 얼마나 위험한가 | 다섯 항목 각각 |

**축을 합치지 않는다.** 서로 어긋나도 된다.
분류가 D인데 진위가 신뢰성 높음일 수 있고, 진위가 미확인인데 위험도가 치명일 수 있다.

**위험도에 진위를 반영하지 않는다.** 미확인이라고 위험도를 깎으면 실제 위험을 과소평가한다.
진위 미확인에 위험도 치명은 사실이면 치명이라는 뜻이고 확인 우선순위가 가장 높다.

## 권고를 낸다

⑥ 마지막에 권고를 낸다. 세 갈래다.

    추가 조사 가능한 것    우리가 더 확인할 수 있는 것
    확인이 필요한 것       대상 조직이 자기 시스템에서 대조할 것
    즉시 조치가 필요한 것   사실 여부와 무관하게 지금 할 수 있는 것

**권고는 판정이 아니다.** 진위가 미확인이어도 낸다.
사실이라면 무엇을 해야 하는지이고, 위험도 다섯 항목이 근거다.

정보를 나열하고 끝내면 조사 메모지 보고서가 아니다.

## 재료 파일을 받으면 먼저 종류와 크기를 본다

**통째로 읽으려 하지 마라.** 유출물 파일은 사람이 읽을 크기가 아니다.
mysqldump 는 한 줄이 수 MB 다. 잘라 읽으면 첫 줄부터 실제 개인정보가 들어온다.

| 받은 것 | 무엇으로 |
|---|---|
| `.sql` 덤프 | `tools/db_tree.py` 로 표 구조부터 |
| 압축 목록, 파일 경로 목록 | `tools/tree_scan.py` |
| 샘플 몇백 줄 (CSV·텍스트) | 그대로 읽어 ④에 넣는다 |
| 1MB 넘는 파일 | 그대로 읽지 마라. 위 도구를 쓰거나 사람에게 잘라 달라고 한다 |

    python tools/db_tree.py <덤프.sql> --md 구조.md
    python tools/tree_scan.py <목록파일> --md 트리.md

둘 다 이름과 건수만 읽는다. 값을 출력하지 않는다.
그래서 유출물이 있는 기계 안에서 돌리고 출력만 가져와도 된다.

**크기를 안 보고 Read 부터 하지 마라.** 컨텍스트가 터지거나 원문이 들어온다.

## 도구는 스킬 안에 있다

`tools/` 가 이 스킬 폴더 안에 함께 설치된다. 프로젝트 폴더 밖에서 불려도 돈다.

    tools/notion_find.py    팀 DB 조회
    tools/notion_row.py     DB 행 생성
    tools/notion_push.py    페이지 올리기
    tools/notion.py         읽기 래퍼
    tools/tree_scan.py      파일 경로 목록 분석
    tools/tree_rules.json   트리 규칙
    tools/db_tree.py        SQL 덤프의 표 구조 분석

경로가 안 잡히면 스킬 폴더를 기준으로 부른다.

    python <스킬폴더>/tools/notion_find.py 수집 <대상>

**도구가 없다고 넘어가지 마라.** 스킬 폴더 안을 먼저 찾는다.
그래도 없으면 못 봄에 도구 부재라고 적는다.

## 팀 DB 대조를 먼저 한다

②에서 가장 먼저 하는 것은 **이 건이 이미 팀 DB에 있는지 보는 것**이다.

```
python tools/notion_find.py 수집 <대상 도메인 또는 게시자 핸들>
python tools/notion_find.py 검증 <대상 조직>
```

**사건 ID로 찾지 않는다.** 노션이 자동 부여하므로 조사 시점에는 없다.
사람이 읽는 값으로 찾는다. 대상 조직, 대상 도메인, 게시자 핸들.

안 하면 같은 건을 두 번 검증하고, 기존 줄에 있는 값을 못 봄으로 적게 된다.

**팀 DB가 없는 환경이면 건너뛴다.** 안 봄(팀 DB 없음)으로 적고 그대로 진행한다.
노션 없이도 ②④⑤⑥은 전부 돈다. 빠지는 것은 중복 대조와 ⑨ 자동 입력뿐이다.

## 파일 트리

확보한 유출물의 구조를 분석하는 재료다. 값이 아니라 이름과 구조라 원문 그대로 본다.
`references/tree-analysis.md` 를 읽는다.

**마스킹으로 분석을 약하게 만들지 않는다.** 분석은 원문 경로로 하고,
파일명 자체에 개인정보가 있으면 산출물에 실을 때만 가린다.

## 하면 안 되는 것

| | 왜 |
|---|---|
| 토큰이나 자격증명이 살아있는지 확인하려고 요청을 보내는 것 | 남의 자격증명을 실제로 쓰는 행위다. 존재와 패턴까지만 기록한다 |
| 유출 파일을 내려받는 것 | 다운로드 링크는 존재만 기록한다 |
| 유출물 파일을 통째로 읽으려 하는 것 | 종류를 보고 도구를 먼저 쓴다 |
| 유사 상호나 유사 도메인으로 갈아타는 것 | 도메인은 문자 단위로 대조한다 |
| 대상 조직 사이트에 로그인 시도, 경로 추측, 취약점 점검 | 공개 페이지 조회는 되지만 이건 능동 행위다 |
| 대상 문자열이 없는 문서를 출처로 적는 것 | 최종 출처 목록까지 확인한다 |
| 검색으로 못 찾은 것을 없음으로 적는 것 | 못 봄에 수단과 질의를 적는다 |
| 게시하는 것 | 초안까지만. 게시는 사람이 한다 |

## 정본

**정본은 이 레포다.** 스킬과 노션 사본이 다르면 레포가 맞다.
수집 DB와 검증 DB, 회의록과 조사 자료의 정본은 노션이다.

바뀐 내역은 `git log` 를 본다. 팀이 아직 안 정한 항목은 노션 사본 끝에 있다.
